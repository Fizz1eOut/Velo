# Velo

**Velo** — это realtime-мессенджер (SPA/SSR на Nuxt 4) на базе Supabase Realtime. Пользователь может зарегистрироваться и войти в аккаунт, вести личную переписку с вложениями, реакциями и ответами на сообщения, видеть статус собеседника и индикатор набора текста в реальном времени, искать по истории переписки, настраивать профиль и управлять чатами (очистка, удаление, блокировка пользователей).

---

# Основные возможности

## Регистрация и вход

* **Регистрация** по email, паролю, имени и юзернейму с клиентской валидацией через VeeValidate + Yup: имя с заглавной буквы, юзернейм 3–10 символов, подтверждение пароля, обязательное согласие с условиями использования (Terms of Service, Privacy Policy).
* **Вход** по email и паролю с отображением ошибок.
* **Восстановление пароля:** отправка формы запроса восстановления и отдельная страница установки нового пароля с подтверждением.
* **Единая страница `/login`** с переключением между тремя состояниями (Sign in / Sign up / Forgot password) без перезагрузки — переключение управляется локальным состоянием, заголовок вкладки обновляется динамически через `useHead`.
* **Двухколоночный layout авторизации:** приветственный экран с превью чата и бейджами возможностей слева (скрывается на мобильных), форма — справа.
* Показ/скрытие пароля через переключаемую иконку глаза на всех формах, связанных с паролем.
* **Навигационные guard-ы:** защищённая (`auth`) и гостевая (`guest`) middleware — авторизованный пользователь не может попасть на страницы входа, неавторизованный не может попасть в чаты.

## Чаты и список бесед

* **Sidebar с беседами:** список всех чатов пользователя с превью последнего сообщения, временем и меткой непрочитанных сообщений.
* **Realtime-обновление списка** через Supabase channels: новое сообщение мгновенно обновляет превью и счётчик непрочитанных без перезагрузки страницы.
* **Отслеживание статуса пользователей** (`online` / `offline` / `dnd`) в реальном времени — статус собеседника в сайдбаре обновляется мгновенно при изменении в базе.
* Индикатор «онлайн» вычисляется по `last_seen` с окном в 2 минуты — если пользователь не отправлял heartbeat дольше этого времени, он считается оффлайн, даже если статус в БД ещё не обновился.
* **Адаптивная раскладка:** на мобильных экранах список чатов и окно переписки переключаются как отдельные экраны (список ↔ чат) вместо отображения бок о бок.
* Поиск пользователей для создания нового чата через `AppSearch`.

## Окно переписки

* Загрузка чата по `userId` собеседника с обработкой состояний загрузки и ошибки.
* **Realtime-подписка на удаление чата:** если собеседник (или текущий пользователь) удаляет чат, окно переписки закрывается автоматически.
* Автоматическая очистка realtime-подписок и таймеров при размонтировании компонента (`onUnmounted`) и при смене активного чата.
* **Изолированный контекст на каждый чат:** поиск по сообщениям, набор текста и активный reply передаются вниз через `provide/inject` (композаблы `useChatSearch`, `useChatTyping`, `useChatReply`), что позволяет держать логику окна переписки декларативной и переиспользуемой.

## Отправка сообщений

### Основные операции

* Отправка текстовых сообщений по кнопке или клавише Enter (Shift+Enter — перенос строки).
* Блокировка повторной отправки, пока предыдущее сообщение или вложение ещё отправляется.

### Вложения

* Поддержка изображений, видео, аудио, PDF, документов и архивов — загрузка через `sendAttachment`.
* Файлы хранятся в приватном Supabase Storage bucket и раздаются через временные подписанные URL (`createSignedUrl`) сроком на час, с retry при ошибке получения ссылки.
* Просмотр изображений в лайтбоксе по клику.
* Отображение файлов с иконкой, названием и человекочитаемым размером (B/KB/MB/GB).

### Ответы на сообщения

* Выбор сообщения из контекстного меню, превью цитируемого сообщения над полем ввода с возможностью отмены.
* При ответе на удалённое сообщение или медиа-вложение превью адаптируется («Message deleted», «Photo», «Video» и т.д.).

## Реакции на сообщения

* Быстрые реакции (👍 ❤️ 😂 🔥 😮 😢) через контекстное меню сообщения.
* Один пользователь может иметь только одну активную реакцию на сообщение — при выборе новой предыдущая снимается автоматически.
* **Оптимистичное обновление UI:** счётчик и список реагирующих обновляются на клиенте мгновенно (`applyLocalReactionToggle`) до подтверждения от сервера.

## Контекстное меню сообщения

* Позиционируемое меню, открывающееся в точке клика, с автоматической корректировкой позиции, чтобы не выходить за границы экрана.
* Доступные действия: реакция, ответ на сообщение, копирование текста, удаление собственного сообщения (только для автора).

## Индикатор набора текста (Typing indicator)

* Реализован через Supabase Realtime broadcast-каналы (`private: true`) — без обращения к базе данных.
* Автоматическая отправка события «печатает» при вводе текста и события остановки — через 3 секунды бездействия или при отправке сообщения.
* **Устойчивость к состоянию гонки:** события, отправленные до полной подписки на канал, ставятся в очередь и досылаются после подтверждения подписки.

## Статус «онлайн» и heartbeat

* При входе в приложение клиент отправляет heartbeat каждые 30 секунд, поддерживая статус `online`.
* Автоматическая установка статуса `offline` при закрытии вкладки (`beforeunload`) и уходе вкладки в фон (`visibilitychange`), и обратно в `online` при возврате.

## Поиск по переписке

* Полнотекстовый поиск по загруженным сообщениям текущего чата.
* Навигация между найденными совпадениями (вперёд/назад) со счётчиком «текущее / всего».
* Анимированное раскрытие поисковой строки поверх заголовка чата.

## Toast-уведомления о новых сообщениях

* **Глобальная realtime-подписка** на новые сообщения во всём приложении (Nuxt-плагин `messageToast.client`) — уведомление показывается независимо от того, открыт ли этот чат в данный момент.
* Тост содержит аватар, имя отправителя, текст сообщения и время; автоматически скрывается через заданное время.

## Управление чатом

* Контекстное меню чата с подтверждением через переиспользуемый композабл `useConfirm` (модальное окно да/нет с опасным вариантом оформления).
* **Очистка истории** чата без его удаления.
* **Удаление чата** целиком.
* **Блокировка пользователя** — заблокированный больше не может писать и видеть профиль, текущий чат с ним удаляется.

## Профиль пользователя

### Просмотр и редактирование

* Просмотр и редактирование профиля через выдвижную боковую панель (`AppSidebar`).
* **Поля профиля** (имя, юзернейм, био) редактируются inline: клик по полю превращает его в поле ввода с кнопками Save/Cancel, значение сохраняется только если оно действительно изменилось.
* Отдельный компонент для биографии с ограничением длины и live-счётчиком символов.

### Аватар

* Загрузка изображения с клиентской валидацией (тип файла, лимит 5MB).
* Индикатор загрузки поверх аватара, мгновенное обновление после сохранения.

### Отображение собеседника

* Компактный компонент `ProfileIdentity` для отображения краткой информации о собеседнике (аватар, имя, юзернейм) в шапке чата.

## Архитектура и производительность

* **Композаблы** как основной механизм расшаривания сквозной логики поверх `provide/inject` (поиск и typing в чате, контекстные меню, подтверждения, тосты и т.д.).
* **API-слой** чётко разделён по доменам (auth, чаты, сообщения, пользователи, блокировки) — каждый файл отвечает за одну операцию; компоненты и сторы не обращаются к Supabase напрямую, а идут через эти функции.
* **Nuxt-плагины** (`messageToast.client`, `status.client`) инициализируют глобальные realtime-подписки один раз при старте приложения на клиенте.
* Утилиты (`utils/`) для форматирования дат сообщений, вычисления онлайн-статуса, дебаунса и группировки реакций вынесены отдельно от компонентов и полностью покрываемы юнит-тестами.
* Работа с темой оформления (`themeStore`) — переключение light/dark с сохранением выбора в `localStorage` и применением класса на `<html>`.

## UI / UX

* Кастомная дизайн-система компонентов (`AppButton`, `AppInput`, `AppIcon`, `AppAvatar`, `AppDropdown`, `AppSidebar`, `AppDivider` и др.).
* Тёмная тема по умолчанию с возможностью переключения на светлую.
* Полная адаптивность интерфейса: десктопный двухпанельный вид и мобильный режим с переключением экранов.
* Плавные переходы и анимации (появление поисковой строки, оверлей загрузки аватара, hover-эффекты).

## Технологии

* **Nuxt 4** — фреймворк (SSR/SPA)
* **Vue 3 (Composition API)**
* **TypeScript**
* **Pinia** (`@pinia/nuxt`) — управление состоянием
* **Supabase** (`@nuxtjs/supabase`, `@supabase/supabase-js`) — база данных, аутентификация, Storage, Realtime (Postgres Changes + Broadcast)
* **Vee-Validate + Yup** — валидация форм
* **Vitest** (`@nuxt/test-utils`, `@vue/test-utils`, `happy-dom`, coverage-istanbul) — юнит-тестирование
* **unplugin-auto-import**, **vite-svg-loader** — автоимпорт и работа с SVG

## Установка

```bash
git clone https://github.com/Fizz1eOut/Velo.git
cd Velo
npm install
npm run dev
```

> Для работы приложения необходимо создать файл `.env` и добавить переменные окружения Supabase:
> ```
> SUPABASE_URL=your_supabase_url
> SUPABASE_KEY=your_supabase_anon_key
> ```
